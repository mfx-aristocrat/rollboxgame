# RollboxGame

**Switchback Couriers** is a Roblox rooftop delivery game: switch your parcel between Amber and Cyan to pass matching gates, deliver, earn shells and beat your best time. `develop` contains the initial Training slice; `main` holds the validated build foundation until required Studio tests pass. This is not a release-ready game.

The complete brief is [Roblox_Game_Creation_Instructions.md](Roblox_Game_Creation_Instructions.md). See [project state](PROJECT_STATE.md) for verified progress and blockers and [roadmap](game_creation_steps.md) for milestone gates. The initial beginner obby instructions are preserved in [docs/original_obby_guide.md](docs/original_obby_guide.md).

## Requirements and setup

- Windows or Linux x86_64, PowerShell 7.2+, Python 3.12+ and Git.
- Network access to official GitHub releases for first-time setup.
- Roblox Studio on a supported computer for runtime validation and publishing. Studio is not bundled or installed by the setup script.

```powershell
git clone https://github.com/mfx-aristocrat/rollboxgame.git
cd rollboxgame
git switch develop
./scripts/setup-tools.ps1
./scripts/check.ps1
./scripts/build.ps1
```

Setup installs the exact Rojo/Lune versions from `tools.lock.json` to ignored `.tools/bin`, verifying archive SHA256 before extraction. Checks compile all Luau source, run pure-rule test suites, build the place, inspect its script mapping and compare two builds byte for byte. Automated checks do not execute Roblox engine behavior.

Build output: `build/RollboxGame.rbxlx` (generated, ignored by Git). Open this file with Roblox Studio. The place's runtime world/UI are generated by source scripts when a playtest starts. A build is not a playable-runtime validation result.

## Studio synchronization and source of truth

The repository is authoritative for Luau, world/UI generation and configuration. To use live synchronization, install the matching official [Rojo Studio plugin](https://rojo.space/docs/v7/getting-started/installation/) and run:

```powershell
./.tools/bin/rojo serve default.project.json
```

Use `rojo.exe` on Windows if your shell requires the extension. Connect the plugin to the local Rojo server in Studio. `src/shared` maps to ReplicatedStorage/Shared, `src/server` to ServerScriptService/Server, and `src/client` to StarterPlayerScripts/Client. Rebuilding and reopening the place is supported without the plugin.

Use Studio edits as experiments. Translate approved map/UI changes back into source before building again. If a future asset must be authored in Studio, export it to a tracked Rojo-compatible model and record its source/license; do not rely on an untracked place as the only copy.

## Development and publishing

Follow [AGENTS.md](AGENTS.md). Develop on `develop`; merge only validated milestones into `main`. CI runs the same checks on Windows and Linux and uploads a generated place artifact. Follow [Studio validation](docs/studio_validation.md) and inspect `PROJECT_STATE.md` before assuming any test has passed. Automated checks compile Luau syntax and exercise pure rules; they are not a Luau type analysis or Roblox runtime test.

Keep test experiences private. Publishing requires the owner's Roblox account and current [Roblox publishing requirements](https://create.roblox.com/docs/production/publishing/publish-games-and-places). Open the generated place in Studio, publish to a private test experience, and verify the account configuration/runtime gates before considering release. Public publishing and paid expenditure require explicit user approval. Configuration, test/prod data isolation and rollback instructions will be expanded with the relevant milestones.

## Training slice controls and configuration

Start a Studio playtest. Use ordinary Roblox movement/jump/camera. At the depot, use E/the touch prompt or **Take parcel**. Switch polarity with Q or **Switch** and cross gates 1–4 in order. Wrong polarity/falling returns you to the last safe checkpoint; resetting your character cancels the run. The left detour avoids the jump shortcut. Reach the green pad to earn 25 coins. Deliver twice, open **Shells**, unlock Mint for 50 coins and equip it. Timers and all rewards are controlled by the server.

The build defaults to **Practice**: progress resets on leaving. Persistence implementation is present but **disabled** until private Roblox configuration/runtime tests pass. See [persistence setup](docs/persistence.md) for the exact `src/server/ServerSettings.luau` fields, universe-ID checks and isolated test/production stores. Cosmetic pass ID is 0/disabled, with no purchase button. There are no developer products. Three-route release content is intentionally gated on the first slice's observed playtests.

For private publishing, account prerequisites and rollback, use [deployment instructions](docs/deployment.md). No experience has been published by the agent, and no paid or public action has been taken.
